## 실제 에이전트 실행

Codex CLI 0.154.0에서 설치된 `aiwf-workflow`와 core review 스킬을 발견하고 읽었다. `gpt-6-astra`가 기존 UC-001의 지출 제출 **서비스 범위**를 구현했다. 정상 제출·금액 오류·비정상 숫자·저장 실패 시 기존 기록 보존을 다루는 실제 Node 테스트 12개가 통과했다. UI와 로그인 구현은 범위에서 제외했다.

계획 작성 → 실제 구조 검사 → pin → 실제 서비스 테스트 → check → evidence → packet 저장·재읽기를 수행했다. Main이 서비스 테스트를 별도로 다시 실행했고, packet의 로그 본문·SHA256·크기와 명세 파일 hash를 대조했다. packet은 `awaiting_review`, acceptance는 `not_recorded`; 4개 실행 검사와 4개 `not_run`을 보존했다. Codex 자체 의미 검토는 별도 검토자의 승인으로 간주하지 않았다.

Claude Code 2.1.287과 `claude-sonnet-5-5`로 실제 `/aiwf-core:spec-review`를 로드했다. bundled checker와 review checklist를 사용했다. 구조 검사와 추적표 출력은 서로 다른 실행 모드이므로 분리해서 확인했다. 의미 검토에서는 예제 명세의 확인 불가능한 사전조건, 저장 실패 후 재시도/입력 상태, 사용 내용의 필수 여부에 대해 경고 3개와 정보 3개를 보고했다. 구조 검사 통과를 의미 검토 통과나 승인으로 바꾸지 않았다.

## 발견하고 수정한 오류

기존 폴더를 packet 저장 대상으로 지정하고 `--force`를 쓰면 원시 `EISDIR` 오류가 노출됐다. 저장 대상이 일반 파일인지 확인해 `output_not_file`로 거부하도록 수정했다. 강제 여부 두 경우 모두 폴더와 내부 사용자 파일 보존을 검증하는 회귀 테스트를 추가했다. 수정한 실제 npm 설치본의 `--json` 오류 코드와 파일 보존도 확인했다.

## 실행 중 확인한 환경 문제와 한계

- 현재 Codex CLI 설정의 `gpt-6.1-sol`은 이 ChatGPT 계정으로 거부됐다. 계정 모델 목록의 `gpt-6-astra`를 명시한 뒤 실제 실행이 완료됐다. 사용자 전역 설정은 변경하지 않았다.
- 첫 Claude 검사에서는 모델이 허용된 Python 명령에 추가 명령을 붙여 실행 권한이 거부됐다. 허용 범위를 넓히지 않고 단일 Python 명령으로 다시 실행했으며 최종 실행은 권한 거부 없이 완료됐다.
- 4개 stack은 설치·리소스·명령 매핑을 검증했다. 각 framework의 실제 프로젝트 생성·빌드·브라우저/E2E 동작은 이번 결과에 포함되지 않는다.
- 최소 지원 버전 Node 20/Python 3.9는 설치되어 있지 않아 해당 버전 실행은 검증하지 않았다.
- 운영 앱 UI·인증·업무 수용, Sprintable 동기화·승인, 무인 반복 실행은 미검증 또는 미구현이다.
