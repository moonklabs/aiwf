## 변경·검증 원칙

BR-002 검사 이름은 ASCII/astral Unicode의 200/201 경계, 숫자·배열·객체 타입 거부, 생략·null·빈 문자열 정규화와 TC-002의 201→200 수정 흐름을 식별한다. 기존 기록이 있는 상태에서 잘못된 입력이 기록을 바꾸지 않는지 검증한다. TC-002의 화면 메시지와 로그인은 C-UI에 남긴다.

명세·매핑·명령 변경은 pin drift로 확인한다. 코드·테스트의 bytes hash는 실행 기록에서 별도로 남기며 current CLI가 이를 검증한다고 주장하지 않는다. 새로운 명세에서 과거 성공 로그를 사용하지 않고 해당 단계의 명령을 다시 실행한다.

이 파일은 pin에 포함된 검토 문서다. 현재 CLI는 표에 있는 명령을 자동 실행하지 않는다. 실패와 not_run을 보존하고 packet은 awaiting_review로 유지한다.
