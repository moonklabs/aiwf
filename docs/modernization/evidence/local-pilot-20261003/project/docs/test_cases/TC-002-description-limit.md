# Test Case: 사용 내용 길이 수정 후 제출

## Overview

**ID:** TC-002  
**Goal:** 사용 내용 길이 오류 후 수정하여 접수하는 UC-001 BR-002/A3 흐름을 확인한다.  
**Priority:** High  
**Status:** Draft  

## Roles

- 제출자 (사용 내용을 수정하고 제출한다)

## Preconditions

- 제출자 계정이 준비되어 있다 (UI는 이번 파일럿에서 미실행)
- 기존 지출 내역 1건이 저장되어 있다

## Flow

| Step | Name | Description | Test Data | Use Case |
|------|------|-------------|-----------|----------|
| 1 | 제출 시작 | 제출자가 지출 내역 제출을 시작한다 | - | [UC-001](../use_cases/UC-001-submit-expense.md) |
| 2 | 길이 초과 입력 | 제출자가 금액과 사용 내용을 입력한다 | 12000, a 201개 | [UC-001](../use_cases/UC-001-submit-expense.md) |
| 3 | 오류 확인 | 사용 내용 길이 오류와 기존 기록 보존을 확인한다 | - | - |
| 4 | 사용 내용 수정 | 제출자가 사용 내용을 수정한다 | a 200개 | [UC-001](../use_cases/UC-001-submit-expense.md) |
| 5 | 제출 확정 | 제출자가 제출을 확정한다 | - | [UC-001](../use_cases/UC-001-submit-expense.md) |
| 6 | 접수 확인 | 새 접수 번호와 최종 내용을 확인한다 | - | - |

## Validation

1. **길이 경계**: ASCII 및 astral Unicode 각각 200 code points는 저장되고 201은 기록 전에 거부된다.
2. **타입·선택 입력**: 숫자·배열·객체는 거부되고 생략·null·빈 문자열은 빈 문자열로 기록된다.
3. **기존 기록 보존**: 모든 거부 후 이전 기록은 변경되지 않는다.
4. **수정 접수**: 사용 내용을 201에서 200으로 수정한 뒤 새 접수 번호로 저장된다.

## Postconditions

- 이전 지출 내역 1건과 새 제출 1건이 남는다.
- 새 내용은 a 200개이며 새 접수 번호가 기록된다.

서비스 검사는 저장·거부·수정만 다룬다. 로그인·화면·오류 표시·접수 화면은 미검증이다.
