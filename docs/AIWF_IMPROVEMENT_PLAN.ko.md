시작일: 2026-10-03 (Asia/Seoul)

## 목표와 첫 작업 범위

현재 저장소에서 재현되는 실행·배포 문제를 먼저 줄이고, 설치 경로에 맞는 검증 기준을 마련한다. 첫 작업은 npm 플러그인 배포 누락과 명령어 검증기의 실패 종료 코드 수정이었다. 이어진 사용자 요청에 따라 공식 skills.sh 설치 및 Codex 지원을 다음 작업으로 진행한다. 초기 플러그인 hook 정비 순서보다 이 요청을 우선한다.

## 구현과 검증 순서

1. 변경 전 `npm pack --dry-run --ignore-scripts --json`과 명령어 검증기 실행 결과를 기록한다.
2. 실제 npm 파일 목록을 읽는 배포 회귀 테스트와 임시 디렉토리에서 검증기를 실행하는 CLI 회귀 테스트를 먼저 추가한다.
3. `package.json`의 배포 목록과 `scripts/validate-commands.js`를 최소 변경한다. 의존성을 추가하지 않는다.
4. 새 테스트, `npm run check:deps`, CLI 도움말, 변경 파일 문법 검사와 `git diff --check`를 실행한다.
5. 기존 전체 테스트의 결과는 별도로 기록한다. 이번 회귀 테스트의 통과를 전체 안정화 완료로 간주하지 않는다.

## 위험과 대응

- 플러그인 파일 포함은 배포 누락만 해결한다. hook·skill·외부 에이전트 참조는 다음 작업에서 각각 검증한다.
- 검증기 종료 코드 수정 후 현재 저장소의 기존 불일치가 자동화에서도 실패로 표시된다. 정상·실패 fixture를 분리해 종료 코드 계약을 검증한다.
- 기존 URL 검사 결과도 `success`의 일부이므로 실패 종료에 반영된다. 이번에는 URL 규칙을 변경하지 않았으며, 공식 저장소 URL 및 언어별 전용 명령어의 예외 정책은 후속 검증기 정비에서 검토한다.
- 전체 테스트에 이전 구조와 삭제된 기능을 전제로 한 테스트가 남아 있다. 실패 기준을 낮추거나 테스트를 숨기는 대신 후속 작업으로 분류한다.
- `lint`·`typecheck` 명령은 현재 `package.json:12`에 없다. 이번에는 문법 검사와 의존성 검사로 검증하고 검증 도구 정비는 후속 작업으로 남긴다.

## 첫 작업 검증 결과

- 기준 환경: Node 22.23.1, npm 10.9.8. 기존 lockfile로 의존성을 설치했고 새 의존성은 추가하지 않았다.
- 변경 전 전체 테스트: `npm test -- --runInBand` 기준 15개 suite 중 2개 통과, 13개 실패. 테스트는 78개 통과, 34개 실패, 20개 건너뜀이며, suite 실패 중 5개는 누락 모듈 또는 빈 suite 등으로 실행하지 못했다. 커버리지 80% 기준도 실패했다.
- 배포 회귀 테스트: 수정 전 네 플러그인 검사가 모두 실패했고, `plugins/` 추가 후 5개 검사가 모두 통과했다. 배포 목록의 플러그인 파일은 0개에서 120개로 늘었다.
- 의존성 검사와 메인 CLI 도움말: 통과. 도움말 통과가 설치 기능 전체의 정상 동작을 증명하지는 않는다.
- 검증기 회귀 테스트: 수정 전 실패했던 불일치·빈 디렉토리·누락 디렉토리의 종료 코드 검사와 공개 반환값 검사를 포함해 6개가 모두 통과했다. 기존 `validateCommands()` 반환 필드도 유지했다.
- 통합 회귀 검증: 아래 명령으로 신규 테스트 11개가 모두 통과했다. 전역 커버리지 기준은 기존 전체 테스트 기준선으로 별도 기록하며, 이 명령은 두 변경의 동작만 검증한다.

  ```bash
  npm test -- --runInBand --coverage=false --runTestsByPath tests/package-distribution.test.js tests/validate-commands-cli.test.js
  ```

- 실제 저장소의 명령어 검증: 기존 8개 불일치가 남아 있어 종료 코드 1을 반환한다. 검증기가 문제를 감지하는 동작은 수정됐고, 불일치 자체의 정리는 후속 작업이다.
- 변경한 JavaScript 파일의 `node --check`와 `git diff --check`: 통과. 현재 lint·typecheck 명령이 없어 해당 검증은 수행하지 않았다.
- 독립 코드 리뷰: 차단할 결함 없음. 실패 메시지 검사를 구체화하고 빈 디렉토리 실패 원인과 공개 반환 필드를 회귀 테스트로 보강했다. 신규 로드맵 문서는 기존 `docs/` 배포 정책에 따라 npm 패키지에도 포함한다.

첫 작업은 완료했다. 후속 사용자 요청에 따라 다음 작업은 아래의 표준 스킬 설치 및 Codex 지원이다. 플러그인 hook 문제는 기존 경로의 후속 작업으로 남긴다.

## skills.sh 설치 및 Codex 지원

사용자 요청: 공식 `npx skills add` 설치 방식과 Codex를 지원한다.

- 기존 6개 스킬의 콜론 이름을 `aiwf-*` 표준 이름·디렉토리로 이동한다. 기술 참고 자료는 보존하고, 진입점의 전용 hook·외부 명령·하드코딩된 경로/인증 의존성을 제거한다.
- 독립 `skills/aiwf/`에 초기화·계획·구현·검토·재개 절차와 템플릿을 포함한다. 선택적 Node helper는 설치 폴더 안의 자료로만 동작하며 기존 파일을 덮어쓰지 않는다.
- 영문·국문 README 및 [설치 가이드](SKILLS_INSTALLATION.md)를 표준 스킬 경로로 정리한다. 기존 플러그인은 별도 호환 경로로 남긴다.
- 완료 기준은 메타데이터/파일 참조 검사, 실제 공식 CLI의 스킬 발견·두 에이전트 설치, 설치본 helper 실행, 기존 문서 보존과 읽기 전용 상태 조회, 독립 에이전트의 실제 작업 수행이다.
- GitHub에 반영하기 전에는 로컬 경로 설치를 사용한다. npm 발행이나 원격 반영은 이번 작업 범위에 포함하지 않는다.

### 스킬 업데이트 검증 결과

- 변경 전 스킬 메타데이터·카탈로그 검사 8개와 설치본 helper 검사 6개가 실패했다. 표준 이름/자료 경로 정리 및 helper 구현 후 통과했다. 빈 metadata가 다음 줄을 읽는 오류는 별도 실패 회귀를 확인하고 수정했다.
- 독립 리뷰에서 기존 본문 형식 태스크의 누락, BOM frontmatter 누락, 프로젝트 이름의 `$` 치환 문제를 발견했다. 실패 회귀를 먼저 확인하고 수정했으며 기존 형식은 경고를 통해 원문/상태 index 확인을 요구한다.
- 최종 `npm run test:skills`: 4개 suite, 38개 테스트 통과. 기존 전체 Jest 실패 및 커버리지 기준은 위 기준선과 별도로 관리한다.
- `npm run test:skills-install`: 공식 `skills@1.7.0`으로 임시 프로젝트의 Codex/Claude Code에 7개 스킬 설치를 검증했다. 기본 연결 방식과 `--copy` 방식 모두 자료가 원본과 동일하고 설치본 helper가 동작한다. 외부 source checkout을 런타임에 참조하지 않는다.
- 독립 실행 에이전트는 설치본만 읽고 별도 Node 프로젝트를 초기화한 뒤 온도 변환 기능을 구현했다. 테스트 6개 통과, 태스크 `done`, 한국어 manifest/progress 갱신, 기존 README/지침 보존을 메인에서 다시 확인했다.
- 기술 참고 파일 30개를 보존했다. 19개는 이전 Git 버전과 동일하며, 백엔드 참고 파일 11개는 잘못된 돌아가기 링크 `SKILL.md`를 `../SKILL.md`로 수정했다. 본문 기술 내용은 유지했다. 링크 회귀 검사는 스킬 진입점뿐 아니라 전체 Markdown 자료를 확인하며, npm 배포 검사는 각 스킬의 스크립트·자료·템플릿 전체를 포함한다.
- `npm run check:deps`, JavaScript 문법 검사, 새 설치 문서의 상대 링크 검사, `git diff --check` 통과. 저장소에 새로운 의존성은 추가하지 않았다.
- skill-creator의 선택적 Python 검증기는 PyYAML이 없어 실행하지 못했다. 기존 `js-yaml`을 쓰는 메타데이터/자료 검사 및 실제 공식 설치로 검증했고 Python 의존성을 추가하지 않았다.
- npm 패키지 및 lockfile의 Node 요구사항을 18 이상으로 맞췄다. 외부 공식 설치 도구의 요구사항은 별도로 22.20 이상이다.
- 독립 재리뷰: 차단할 결함 없음. 기존 태스크 경고·BOM·이름 치환·전체 자료 링크·Node 요구사항 수정과 38개 테스트를 재확인했다. 공식 설치 검증은 메인의 실제 CLI 실행 결과로 확인했다.

표준 스킬 설치 및 Codex 지원 업데이트를 완료했다. 공개 저장소 반영 전에는 로컬 경로로 설치한다. 기존 CLI/플러그인 hook 및 전체 테스트 기준선 복구는 별도 후속 작업이다.
