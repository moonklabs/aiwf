# 문서와 함께 계획을 구체화하는 질문 세션

> 휴먼 리뷰용 한글 번역입니다. 실행 원문: [원문 스냅샷](source/SKILL.source.md). 번역과 자동 검사는 승인을 뜻하지 않으며, 검토 상태와 원문 SHA256은 [관리 목록](../../manifest.json)에서 확인합니다.

**식별자:** `grill-with-docs`  
**설명:** 기존 도메인 모델에 비추어 계획을 검토하고 용어를 구체화하며, 결정이 정리될 때마다 `CONTEXT.md`와 ADR 문서를 바로 갱신하는 질문 세션이다. 프로젝트의 용어와 문서화된 결정에 맞춰 계획을 검증하려는 사용자 요청에 사용한다.

## 수행할 일

서로 같은 이해에 도달할 때까지 계획의 모든 측면을 끈기 있게 질문한다. 설계 트리의 각 가지를 따라가며 결정 사이의 의존성을 하나씩 해결한다. 각 질문에는 권장 답변을 함께 제시한다.

질문은 한 번에 하나씩 한다. 각 질문의 피드백을 기다린 뒤 다음으로 진행한다.

코드베이스를 살펴 답할 수 있는 질문이면 사용자에게 묻는 대신 코드를 조사한다.

## 보조 정보: 도메인 파악

코드베이스를 조사할 때 기존 문서도 함께 찾는다.

### 파일 구조

대부분의 저장소에는 하나의 컨텍스트가 있다.

```
/
├── CONTEXT.md
├── docs/
│   └── adr/
│       ├── 0001-event-sourced-orders.md
│       └── 0002-postgres-for-write-model.md
└── src/
```

루트에 `CONTEXT-MAP.md`가 있으면 여러 컨텍스트를 가진 저장소다. 맵은 각 컨텍스트의 위치를 가리킨다.

```
/
├── CONTEXT-MAP.md
├── docs/
│   └── adr/                          ← system-wide decisions
├── src/
│   ├── ordering/
│   │   ├── CONTEXT.md
│   │   └── docs/adr/                 ← context-specific decisions
│   └── billing/
│       ├── CONTEXT.md
│       └── docs/adr/
```

위 예제에서 루트 `docs/adr/`는 시스템 전체 결정, 컨텍스트 안의 `docs/adr/`는 해당 컨텍스트의 결정을 담는다.

파일은 쓸 내용이 생길 때만 만든다. `CONTEXT.md`가 없다면 첫 용어가 확정될 때 생성한다. `docs/adr/`가 없다면 첫 ADR이 필요할 때 생성한다.

## 세션 중 진행 방식

### 용어집에 비추어 질문한다

사용자의 용어가 `CONTEXT.md`의 기존 언어와 충돌하면 즉시 지적한다. 예: “용어집은 '취소'를 X로 정의하는데, 지금 말씀은 Y처럼 들립니다. 어느 의미인가요?”

### 모호한 표현을 구체화한다

사용자가 모호하거나 여러 의미로 쓰이는 용어를 사용하면 정확한 표준 용어를 제안한다. 예: “'계정'이라고 하셨는데 Customer인가요, User인가요? 두 개념은 다릅니다.”

### 구체적인 시나리오를 논의한다

도메인 관계를 논의할 때 구체적 시나리오로 검증한다. 경계 사례를 드러내고 사용자가 개념 사이의 경계를 정확히 정하도록 하는 시나리오를 제시한다.

### 코드와 대조한다

사용자가 어떤 동작을 설명하면 코드도 그 설명과 일치하는지 확인한다. 모순을 발견하면 드러낸다. 예: “코드는 Order 전체를 취소하지만, 방금 부분 취소도 가능하다고 하셨습니다. 어느 쪽이 맞나요?”

### CONTEXT.md를 즉시 갱신한다

용어가 확정되면 그 자리에서 `CONTEXT.md`를 갱신한다. 나중에 한꺼번에 정리하지 않고 확정될 때마다 기록한다. [CONTEXT-FORMAT 한글본](CONTEXT-FORMAT.ko.md)과 [원문](source/CONTEXT-FORMAT.md)의 형식을 사용한다.

`CONTEXT.md`에는 구현 세부사항을 전혀 넣지 않는다. 명세, 임시 메모장, 구현 결정 보관소로 취급하지 않는다. 오직 용어집으로 사용한다.

### ADR은 꼭 필요한 경우에만 제안한다

다음 세 조건을 모두 만족할 때만 ADR 생성을 제안한다.

1. **되돌리기 어렵다.** 나중에 결정을 바꾸는 비용이 상당하다.
2. **맥락 없이는 의외로 보인다.** 미래의 독자가 “왜 이렇게 했지?”라고 생각할 수 있다.
3. **실제 대안 사이에서 선택했다.** 현실적인 대안들이 있었으며 구체적 이유로 하나를 선택했다.

하나라도 충족하지 않으면 ADR을 만들지 않는다. [ADR-FORMAT 한글본](ADR-FORMAT.ko.md)과 [원문](source/ADR-FORMAT.md)의 형식을 사용한다.
