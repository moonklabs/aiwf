# 기획 ↔ 디자인 ↔ 구현 (현재 상태만)

> 휴먼 리뷰용 한글 번역입니다. 실행 원문: [원문](../../../../../../../../plugins/aiwf-design/skills/workflow/references/templates/design-spec/traceability.md). 번역과 자동 검사는 승인을 뜻하지 않으며, 검토 상태와 원문 SHA256은 [관리 목록](../../../../../../manifest.json)에서 확인합니다.

> **현재 상태**만 기록한다. 행이 바뀌면 덮어쓰고 날짜를 갱신한다. 이력은 Git에 있다.
> 기획 ID는 기획 문서의 FR/UC이고, 디자인 단위는 이 폴더의 흐름, 화면, 컴포넌트이며, 구현은 저장소 소스이다. 여기서 기획 문서를 고치지 않는다 — 고쳐야 하면 상태를 `기획 변경 필요`로 하고 [HANDOFF](../../../../../../../../plugins/aiwf-design/skills/workflow/references/templates/design-spec/HANDOFF.md)에 한 줄을 추가한다.

## 상태 값
| 값 | Meaning |
|---|---|
| `기획 없음` | 대응하는 UC/FR 없이 디자인이 있다. 기획이 새 ID를 부여하면 연결한다 |
| `기획 변경 필요` | 디자인 결정이 기존 UC/FR이나 제약과 다르다. 기획이 먼저 결정한다 |
| `기획 변경 대기` | UC/FR이 바뀌어 디자인 검토가 필요하다 (변경한 쪽이 설정) |
| `디자인 완료` | Figma 화면과 컴포넌트가 있고 결정이 decisions.md에 있다 |
| `구현: 이전 디자인` | 기능은 코드에 있지만 새 디자인은 적용되지 않았다 |
| `구현: 새 디자인` | 새 디자인이 코드에 적용되었다 (타입 검사와 빌드) |
| `검증 완료` | 사람이 실제 앱에서 확인했다. 캡처나 인수 문서를 링크한다 |

## Update rules
1. **기획이 바뀔 때**: 바꾼 쪽이 영향받는 행을 `기획 변경 대기`로 하고 HANDOFF "기획 변경 대기"에 한 줄을 추가한다.
2. **디자인이 바뀔 때**: 디자이너가 Figma 열과 상태를 고친다. 기획과 다르면 `기획 변경 필요`로 하고 HANDOFF "아직 결정 안 된 것"에 추가한다.
3. **코드에 적용할 때**: 구현 열과 상태만 바꾼다. `구현: 새 디자인`은 게이트를 통과한 뒤에만 쓰고, 그전에는 이전 상태를 유지하며 미검증 범위를 적는다. 실제 앱 검토 뒤에는 증거 링크와 함께 `검증 완료`로 한다.
4. 행을 덮어쓴다. 행에 과거 상태를 쌓지 않는다.

> 번역자 주: 표의 `Meaning`(뜻) 머리글과 `Flows and screens`(흐름과 화면), `Design system`(디자인 시스템), `Update rules`(갱신 규칙) 헤딩은 원문 템플릿의 영어 그대로이다. `## 상태 값` 헤딩과 표 머리글 상태/갱신은 lint가 읽는 파서 단어이다.
