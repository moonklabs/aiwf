# 한글 검토본 작성 규칙

1. 원문 전체를 읽고 절차·조건·금지 사항·실패 대응을 빠짐없이 한국어로 옮긴다. 요약이나 새로운 지시로 대체하지 않는다.
2. 원문 frontmatter의 `name` 값은 문서 상단에 식별자로 표시한다. `description`은 한국어로 번역한다. 설치용 YAML frontmatter를 만들지 않는다.
3. 각 파일은 `# <한국어 제목>` 뒤에 다음 안내로 시작한다. 원문 링크는 해당 번역 파일에서 원문까지의 상대 경로로 계산한다.

   ```markdown
   > 휴먼 리뷰용 한글 번역입니다. 실행 원문: [원문](상대경로). 번역과 자동 검사는 승인을 뜻하지 않으며, 검토 상태와 원문 SHA256은 [관리 목록](상대경로/manifest.json)에서 확인합니다.
   ```

4. 원문 코드 블록은 내용·순서·언어 태그를 그대로 보존한다. 중첩 Markdown 예제가 바깥 펜스를 닫아 렌더링을 깨뜨릴 때만 바깥 펜스 길이를 늘릴 수 있다. 이 경우 예제 내용은 변경하지 말고, 번역자 주석과 `manifest.json`의 `rendering_adjustments`에 보정 이유와 해당 버전의 SHA256을 기록한다. 명령·경로·ID·버전·API명·파서용 헤딩·상태 단어·플레이스홀더를 번역하지 않는다. 예제의 영어는 코드 호환을 위한 원문이며 필요한 의미 설명을 한국어 본문에 덧붙인다.
5. 본문의 원문 Markdown 링크는 실제 원문 경로로 다시 연결한다. 함께 번역한 참조는 한글 검토본 링크도 제공한다. 원문 앵커 대신 해당 원문 파일을 가리켜도 된다. `.java`, `.tsx`, `.bpmn`, `.py` 등 실행·예제 파일은 원문에 연결하며 번역하지 않는다.
6. 저작권·라이선스·출처 표시는 보존한다. 상충하거나 잘못된 것으로 보이는 원문 지시는 임의로 수정하지 않고 별도 검토 메모로 표시한다. 규범적 지시와 번역자의 설명을 구분한다.
7. 스킬 번역 저장 위치는 `docs/ko-skills/<plugin>/skills/<skill>/SKILL.ko.md`이다. 스킬 참조 Markdown은 같은 폴더 아래 원래 구조를 유지하고 `.ko.md` 확장자를 쓴다. 규칙·프롬프트도 `<plugin>/rules/`, `<plugin>/agents/` 아래에 `.ko.md`로 옮긴다. 각 플러그인 루트 README는 `docs/ko-skills/<plugin>/README.ko.md`에 전체 번역을 두고 원문 링크를 보존한다. README가 추가·삭제·이동·수정되면 번역, 카탈로그, manifest를 같은 작업에서 갱신한다.
8. `manifest.json`은 원문과 번역의 SHA256, 출처, 범위와 검토 상태를 기록한다. 번역자는 완료 후 메인 에이전트에 파일 목록과 누락·불확실한 표현을 보고한다. 사람의 승인 상태를 생성하지 않는다.
